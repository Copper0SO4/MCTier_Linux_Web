## 总体判断

现有架构适合继续维护：浏览器处理媒体和 UI，Rust 管理本地能力，EasyTier 管理虚拟网络；共享信令与媒体逻辑通过构建补丁复用，上游目录保留。当前首要工作是补齐上游更新后的语义兼容，而非继续堆叠功能。能编译不代表能创建大厅或恢复会话。

| 部分 | 当前情况 | 优先方向 |
| --- | --- | --- |
| 大厅/身份/信令 | 复用新版 WebRTCClient，但 Linux 独立入口未同步新版准入模式 | 先修创建、加入及恢复模式 |
| 聊天/附件 | 用户此前验收通过；Rust 部分模块为独立适配副本 | 增加协议差异检查；维护有界传输 |
| 语音/屏幕 | Chrome 双向用户验收；Firefox 1006 未解决 | 长时断线恢复和资源释放专项验证 |
| 文件夹共享 | 私有临时快照，有总量/文件数限制 | 跨端凭据轮换、清理、下载体验 |
| 网络/防火墙 | UFW 用户反馈可 P2P；firewalld 实机与自动重连仍待专项验收 | 修交互状态，核实会话竞态与恢复失败 |
| UI | 独立 DOM 界面，借用原版样式，大面板职责较多 | 统一弹窗、表单状态、布局组件 |
| 发行/维护 | Linux 版本独立，上游补丁生成方式有效 | 固定工具链、稳定标签同步、资产白名单 |

## 需要修正：按优先级

### P1：创建大厅缺少新准入模式

证据：`web/main.ts:318` 调用 `initialize` 只传到 session ticket；`web/index.html:111` 只有加入按钮。上游 `src/services/webrtc/WebRTCClient.ts` 新增第九参数 `entryMode`，默认 `join`，注册消息发送该字段；官方 3.10.0 明确加入不存在的大厅应失败。

影响：此前隐式创建路径不能继续依赖。现有 Linux 入口只能发 join，无法明确创建新大厅。这是源码/协议推导，未进行真实服务器复现。

建议：显式创建/加入按钮或模式；共享同一验证流程；首次创建传 create，已有大厅传 join；服务器已准入后的恢复用 auto，包含虚拟地址冲突重试。不得通过失败后自动 create 来绕过模式边界。接入新版私有服务器能力错误提示。

### P2：界面连接状态与共享 store 脱节

证据：`web/main.ts:329–337` 在注册成功后设置本地 online，再调用 setLobby；新版 `src/stores/appStore.ts:337` 的 setLobby 将 appState/signalingStatus 置为 connecting。Linux 状态回调只改 DOM，没有同步调用 setSignalingStatus，也未像新版 App.tsx 那样最终设置 in-lobby。

影响：界面可能显示已连，但共享 store 仍是 connecting；依赖 store 的后续功能可能误判。当前主要界面独立使用 online，不据此断言所有现有功能立即失效。

建议：统一成功、失败、重连、取消、退出状态更新，成功完成本地会话后再发布 in-lobby/connected。

### P2：防火墙后端切换覆盖先前的处理函数

证据：`web/networkPanel.ts:730–735` 设置 onchange 更新 UFW 出站选项；`:788–791` 又赋值覆盖，只刷新区域和暂停按钮。

影响：firewalld 切回 UFW 后，出站复选框可能仍禁用；UFW 切到 firewalld 时，已勾选值可能残留并发送。需要用一次统一刷新函数维护所有相关控件。

### P2：信令测试模拟数据过期

证据：`tests/signaling-registration.test.mjs:72` 的成功握手 fixture 缺少新版要求的 `lobbyEntryModes: true`；上游客户端收到缺失字段会提前拒绝注册。

建议：更新成功 fixture，另保留旧服务器不支持模式的拒绝用例；覆盖 create/join/auto 与取消/重试。此次未运行测试，因此这里记录为确定的模拟协议不匹配，不报告测试失败数量。

### P2：客户端版本长期写死

证据：`server/src/runtime.rs:613` 返回 defaults.version = 3.8.0，`web/tauriApp.ts` 直接用于共享客户端版本。当前上游包版本为 3.10.0，Linux 发布号为 3.6.0。

目前官方发行说明的最低客户端版本仍是 3.8.0，不能断言因此被拒绝；但版本诊断和今后最低版本判断会失真。建议分别显示 Linux 发行版本、实际兼容的上游版本，构建时生成并校验，不能简单把 Linux 3.6.0 当作上游客户端版本。

## 待进一步验证的风险

- 防火墙变更后 `server/src/network_operations.rs:621` 释放操作锁，再判断会话并执行重连。需要验证同一时刻退出/加入/租约失效是否会使重连落到另一会话；可用 session generation 绑定目标。尚未复现竞态。
- 防火墙成功但 EasyTier 重连失败，API 仍返回成功结构，只在 report 内说明失败；建议结构化返回两种结果，UI 展示部分成功，并依据是否仍有会话决定“重新组网”或“重新加入”。
- firewalld 规则一小时到期；需明确到期状态与提醒策略，不能让 UI 长期暗示仍在放行。当前不建议无提示自动续期。
- Firefox 1006、长时间 ICE 恢复、并发共享/通话、大厅退出后的轨道与计时器释放仍需要受控环境验证，不能从 Chrome 历次通过推导全部完成。

## 优化建议与安排

1. **先恢复兼容性**：上述模式、store 状态、握手 fixture、版本元数据；再修后端切换。此阶段应做自动化和真实创建/加入/取消/重连验收。
2. **把同步变为可重复流程**：sync-upstream.sh 目前只追 master；增加显式稳定标签选择、来源记录与差异摘要。更新后检查补丁不仅能应用，还与实际协议相符。对 server/shared 的手工适配模块建立上游来源/差异清单。
3. **固定构建环境**：目前系统 rustc 无法加载 LLVM；不要依赖 /tmp 下临时编译器。采用持久、固定的 Rust 工具链和可重复 Linux 构建环境，记录 glibc 基线；后续 CI 分别检查前端、Rust、打包和补丁应用。
4. **整理 UI 实现**：networkPanel 约 1030 行，community 约 833 行，main 约 589 行；按网络设置、系统操作、房间管理拆模块。统一对话框焦点/关闭/滚动、操作中禁用状态，减少反复追加 CSS 覆盖。无障碍键盘交互与桌面缩放需浏览器验收。
5. **减少发行冗余**：Vite publicDir 指向全仓 public，web-dist 当前约 123 MiB，其中动画表情约 108 MiB，另有官网截图/赞助图片等非运行必需资源。建议用明确资源清单打包；表情优化保留原版标识/内容映射，不能破坏互通。
6. **再安排新增能力**：文件共享批量操作与下载体验可先做；浏览器下载位置应尊重浏览器授权，不能照搬 Tauri 任意目录接口。录屏之后再做，优先浏览器采集编码 + Rust 分块落盘。远程输入按产品决定不支持，Magic DNS 继续隐藏。
