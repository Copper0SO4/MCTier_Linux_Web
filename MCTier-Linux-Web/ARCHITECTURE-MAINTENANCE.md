# Linux Web 架构维护与后续安排

更新：2026-10-06。官方稳定基线 v3.10.0，Linux 已发布版仍为 3.6.0。此文描述当前源码，不表示新的发行或完整安全审计。

## 维护方式

1. 检查工作树和 HANDOFF，保留全部未提交改动。
2. `scripts/sync-upstream.sh --stable` 获取官方 latest 非预发行标签并审查差异；干净工作树才使用 `--merge`。master 可能包含未发行重构，不能等同稳定版。
3. Windows 共享源码为协议对齐主要依据，Android 为辅助；不猜测信令服务器实现。此次创建/加入对照 WebRTCClient 的 entryMode 和新版能力字段，重连沿用服务器准入后的 auto。
4. 检查 `upstream-sources.json`：四个手工 Rust 适配模块记录官方源文件和 SHA-256。检查失败时逐项阅读新旧协议、配置与传输行为，修正 Linux 适配，再有意更新记录。版本相同也可能存在源码变化。
5. 运行前端/Rust 测试和完整构建。前端生成在 frontend-src，补丁上下文缺失或多处匹配时停止；不得改生成文件绕过失败。
6. 更新根/子 README 和 HANDOFF；真实联机、系统授权另行确认并记录。源码上游版本、可编辑上报版本、Linux 发行号分别描述。

来源哈希只防止维护遗漏，不证明适配正确，也不自动检查全部共享模块。直接引用或脚本生成的模块仍需结合测试审查。

## 职责边界

| 层 | 当前职责 | 维护约束 |
| --- | --- | --- |
| web/main、shell | 大厅生命周期、页面导航、共享 store 同步 | 先统一成功/失败/取消/退出状态，再扩展页面 |
| clientVersion | 版本校验、持久偏好、会话内冻结 | 保存仅影响下次手动加入，重连不切换版本 |
| boundedResponse、download | 有界读取、附件下载、取消 | 无 Content-Length 时仍计数；大小不符拒绝 |
| community | 房主管理、工具、公开广场、共享目录 | 对话框关闭取消全部并发请求；保留原协议 |
| networkPanel | 高级参数、系统操作预览和确认 | 部分成功必须可见，界面封锁不能代替服务端鉴权 |
| runtime | owner 租约、控制 ticket、EasyTier 实例和清理 | 在执行锁内复核，失败清理不得误停新会话 |
| network_operations | 预览 token、系统操作互斥、实例绑定 | 权限由用户确认；规则修改和重连分别返回结果 |
| overlay_http | 聊天/文件虚拟网络 HTTP 策略 | 不走环境代理、不跟随重定向，地址来自已验证对端 |
| binary_response | 有界数据响应和 permit 生命周期 | 流结束或丢弃前保持限流；不是磁盘流式零拷贝 |

MCTier 信令是浏览器 WebSocket；EasyTier 提供虚拟网卡和数据链路。虚拟网络 HTTP 的代理策略不改变信令浏览器的代理行为。大厅在线不证明 P2P 或媒体成功。

## 本次发现与处理

- **旧请求影响新会话**：控制请求在取得许可后可能等待执行；owner 字符串可由同一标签页复用。新增控制 generation ticket，并在启动/退出/重新组网执行时复核。启动失败清理现在持有原 Runtime 锁。
- **防火墙授权期间换房**：按名称/IP 无法区分房间重入。预览绑定 EasyTier 实例 UUID，授权前后与重连都检查；锁不在重连前释放。不把旧预览重连应用到新实例。
- **部分成功误报**：防火墙已改而核心启动失败时，结构化返回 restart failed，UI 显示需要处理的失败；不静默宣布全部完成。
- **环境代理转发虚拟数据**：reqwest 默认读取代理环境。聊天/附件/共享目录统一直连并禁止重定向，测试证明 HTTP_PROXY 存在时目标请求及 fixture token 不交给代理。
- **慢传输跨退出**：附件上传/下载观察聊天 generation，退出取消读取；下载结束后复核对端元数据。共享面板关闭取消多项请求，而非仅最后一项。
- **下载限流过早释放**：响应体创建之后数据可能尚未消费。permit 移入响应流，保持到完成/丢弃；浏览器端限制累计大小和预期大小。
- **维护漂移与资源冗余**：添加来源哈希检查，补丁多义匹配拒绝；停止整体复制 public，仍嵌入全部 566 项官方表情。

这些修复局限在 Linux Web 适配。共享 Windows/Android 源文件没有额外本地修改。

## 验证结果与边界

- 16 个前端测试文件通过；包含新版注册模式、版本冻结、UI 状态、后端切换、部分失败、补丁和有界响应等测试。
- 129 个 Rust 测试通过；新增旧 ticket/旧实例拒绝、慢上传退出取消、响应 permit 保留和环境代理隔离用例。
- TypeScript、Vite（566 项表情）、Rust Debug 编译/链接通过，使用官方校验的 Rust 1.90.0。系统 rustc 的 LLVM 符号错误未修复，临时工具链不是长期方案。
- 本轮未运行真实服务/大厅、浏览器外观验收、pkexec、防火墙变更、跨端媒体或发行打包。历史用户验收仍独立保留；自动化不能替代 Firefox、ICE、RTP、P2P 和重连专项测试。

## 下一步安排

1. **先做真实回归**：Chrome 创建/加入/取消/重入；与 Windows/Android 聊天、并发附件；规则应用成功但重连失败的提示；退房期间授权完成；双向语音/屏幕和断线恢复。Firefox 根因仍未知，入口继续封锁。
2. **补全端到端会话版本**：ticket 主要保护已取得许可后等待执行的核心操作；不是所有 API 都携带浏览器预期的 room epoch。同一标签页旧任务若直到新会话才发请求，可能取得新 ticket。后续先覆盖配置、签名、附件和共享目录，再考虑统一请求封装。
3. **firewalld 到期展示**：规则存在有效期，应准确显示到期与规则状态，不能暗示永久放行；不无提示自动续期。
4. **固定构建环境**：建立固定 Rust/Node 与 glibc 基线的 CI，分别检查补丁、来源、测试、构建和打包；不依赖临时目录工具链。
5. **拆分大面板**：按房主管理、目录共享、网络设置、系统操作拆模块，统一 dialog 焦点/关闭/忙碌处理；每次小步迁移并回归。此次先抽出响应、请求范围和 HTTP 策略，避免一次改写全部 UI。
6. **清理异常遗留**：正常退出和租约回收已有清理，但强杀/崩溃可能遗留私有临时目录；后续设计严格限于本应用目录的回收机制。下载仍会在预算内缓冲，不具备断点续传。

Magic DNS 已按用户新要求开放预览式设置（此前隐藏安排已撤销）；远程输入按产品决定不支持。录屏、系统音频等新能力排在兼容与稳定性之后。不得为了减少文件数量而直接改上游共享实现。

## 2026-10-06 会话诊断优化

新增 sessionGuard 捕获请求所属会话；main 在状态读取与媒体统计返回时复核，旧响应不再误退出新房间。文字发送入口统一复用 sendOutgoing 的迟到结果隔离；状态查询有超时，媒体故障与服务故障分开，统计一次更新避免临时清零。新增回归模拟不代替真实重连验收。官方最新稳定已重新获取，仍为 v3.10.0。
